# Existing texture-family alias port

The implementation copies `texture_backing_format` and its matching boundaries from nxnative Android parity `4fe574ebc` / `ccfd8e118` at `1f01e28c87da5233dfa14fb31fabf1535df33013`. It reuses nx2android's existing storage cache, lifetime and view code. RGBA/RGBX linear/sRGB descriptions share one linear RGBA allocation; BGRA/BGRX use a separate BGRA family. Individual image views retain their original color conversion and alpha mapping.

Matching applies only to memory-backed, nonvirtual, single-sample 2D/2D-array descriptions without packaged initialization data, explicit layouts or linear-storage flags. A key bit preserves the separation between exact packaged identities and shared families within the target's single cache. `tex_t.has_pkg_data` captures `SetPackagedTextureData` at initialization, including when no layout is provided, within the existing 0x80-byte object. Later first-touch, WriteTexels, flush and poll marks affect uploads but never the key, so an existing image remains shared. Existing target color IMAGE flags remain part of the key because they control storage-image usage. This port does not add sharing across those flags, different shapes, unrelated format families, explicit layouts or virtual pools.

`test_texture_format_aliases.py` executes the production key-building block, real cache lookups and NVN initialization with the real NVN types under ASan/UBSan. It checks 64 family combinations, exclusion cases, stable identity after a CPU-write mark, and initialization/reinitialization with packaged data. A compiler probe with the same sanitizer flags produces an explicit skip when the runtimes cannot be linked. The device fixture reuses the donor `recorded_texture_srgb.h` oracle. Its DrawTexture operation is adapted to an ordinary synthetic guest draw using nx2android's existing descriptor/pipeline path, so this PR does not depend on #357. Guest games/assets are unnecessary.

`test_texture_transfers.py` runs the production transfer functions against a Vulkan command recorder. Equal logical formats use raw copies even when the image formats differ; sRGB MSAA resolves first target an equal-format temporary image and then copy bytes into shared backing. Scaled, mirrored and format-converting blits use the logical formats too. Full sRGB clears encode RGB once for UNORM backing and preserve alpha, using a view's format override when present. Unsupported resolve format mismatches are diagnosed and skipped before creating temporary images or issuing a resolve/copy. The tests include nonzero mip/layer/offset selections, both raw-copy directions, same-image format conversions, clear format overrides and unsupported color/depth resolve pairs. This validates emitted commands and clear values, not a GPU implementation.

Build manually on macOS, Linux or Windows with the matching NDK host tools (`clang.exe` and `glslc.exe` on Windows). These commands only build; they do not contact a device:

```sh
python nxnative/dm/android/build.py --game 0100000000010000 --ndk "$ANDROID_NDK_HOME" --out /tmp/alias-host --exe --jobs 8
python tests/run_vk_texture_aliases.py --ndk "$ANDROID_NDK_HOME" --host-build /tmp/alias-host --out /tmp/alias-replay
```

The script only builds. On an authorized device, copy `texture-aliases` and `shaders.dmsv` to a dedicated directory, set `DM_ROOT` to it and run `./texture-aliases`. Use `DM_VK_NO_ZEROCOPY=1` on the emulator. Run all combinations of `DM_VK_RP=0/1`, `DM_VK_UBWC=0/3`, and `NX2A_ALIAS_ARRAY` unset/set to 1.

`NX2A_ALIAS_PACKAGED=1` separately checks actual `SetPackagedTextureData` without a layout: both format orders retain distinct packaged identities and cannot be joined by an alternate-format GPU object.

Each ordinary invocation checks 4,096 pixels: eight source format pairs, both first-writer orders, four alternating clear/sample phases and 64 pixels per phase. Both directions must preserve the donor's sRGB transfer function and X-format alpha=1 behavior while reusing cached views. A control without family sharing fails the first sample (zero instead of 13). Device runs are separate qualification: the host command tests and a successful build do not establish Android GPU or commercial-game behavior. Current run evidence belongs in the PR discussion. Physical-tablet checks of the sRGB window path and sRGB multisample targets remain required before merge.
